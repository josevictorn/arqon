## Escopo
- `src/shared/core/logic/either.ts`:
  - Classes `Left<L, R>` e `Right<L, R>`, tipo `Either<L, R> = Left<L, R> | Right<L, R>` e fábricas `left()` / `right()`.
  - `isLeft()` / `isRight()` como *type guards* (`this is Left<L, R>`), de modo que `if (result.isLeft()) return result` estreite `result.value` sem cast.
  - Helpers mínimos: `map`, `mapLeft`, `flatMap`, `fold` e `combine(eithers[])` (devolve o primeiro `Left` ou `Right` com a tupla de valores, para validar vários VOs de uma vez em `Entity.create`).
- `src/shared/core/errors/domain-error.ts`: classe abstrata `DomainError` com `code` (`<CONTEXTO>.<ERRO>`, ex.: `IAM.WEAK_PASSWORD`), `i18nKey` (`errors.<ctx>.<erro>`, ex.: `errors.iam.weak_password`), `args` (`Record<string, string | number | boolean | null>`, padrão `{}`) e `httpStatus` (número 4xx), todos `readonly`.
- `src/shared/core/errors/common-errors.ts`: `ResourceNotFoundError` (404, `args: { resource, id }`), `NotAllowedError` (403) e `ConcurrencyError` (409, conflito de versão otimista), com códigos `COMMON.*` e chaves `errors.common.*`.
- Testes `*.spec.ts` ao lado de cada arquivo, cobrindo os dois ramos (`left`/`right`) de cada helper, `combine` com lista vazia / só `Right` / `Left` no meio, e os campos de cada erro comum.
- Cobertura obrigatória (ADR-0028): em `vitest.config.mts`, `coverage.thresholds` por glob `src/shared/core/**` = 100 (`lines`, `functions`, `branches`, `statements`), e `pnpm verify` passa a rodar `pnpm test:cov` no lugar de `pnpm test:unit` (mesmos testes + gate de cobertura). Atualizar a linha do `verify` na tabela de comandos do `AGENTS.md` se o texto mudar.
- Remover `src/shared/core/.gitkeep` e corrigir em `src/shared/core/AGENTS.md` o caminho de referência para `logic/either.ts`.

## Notas / riscos
- **`DomainError` não estende `Error`** (ADR-0026): é um valor devolvido em `Left`, nunca lançado. Assim não se captura stack trace (ADR-0013 proíbe stack em 4xx de negócio) e ninguém faz `throw` dele por engano.
- `httpStatus` no erro segue o [07-i18n-and-errors.md](../../architecture/07-i18n-and-errors.md) e as specs, que já fixam o HTTP de cada `code`. Restrinja o tipo a `400 | 401 | 403 | 404 | 409 | 422 | 429`; erro 5xx não é erro de domínio.
- `exactOptionalPropertyTypes` está ligado: `args` opcional no construtor exige `args?: X` e o *default* aplicado no corpo.
- Arquivos só com tipos podem aparecer com 0% no relatório do v8. Se acontecer, exclua-os explicitamente do `coverage.include` e justifique no PR. Não baixe o threshold.
- Gate de cobertura no `verify`: deixa o pre-push um pouco mais lento (cobertura v8 dos unit). Se ficar inviável, a alternativa é um passo `pnpm test:cov` separado no CI. Anote em Follow-ups, não decida sozinho.
