# T1.05 — Enforcement de arquitetura (dependency-cruiser)

- **Fase:** F1 — Fundação e tooling
- **Status:** 📝 Detalhada
- **Depende de:** T1.01
- **ADRs:** [0010](../../decisions/0010-enforcement-de-arquitetura.md)
- **Branch:** `task/T1.05-architecture-enforcement`
- **Tamanho esperado:** M

## Objetivo
Fazer o build falhar automaticamente quando uma regra de camadas ou de isolamento entre módulos for violada. Isso protege a arquitetura de erros (humanos ou de IA) que passariam despercebidos no review.

## Contexto para ler (e só isso)
- [AGENTS.md](../../../AGENTS.md)
- [ADR-0010](../../decisions/0010-enforcement-de-arquitetura.md) (tabela de regras)
- [03-module-anatomy.md](../../architecture/03-module-anatomy.md) (regras de dependência)

## Escopo
- `dependency-cruiser` + `.dependency-cruiser.cjs` com **todas** as regras da tabela do ADR-0010, cada uma com `comment` explicando o porquê e linkando o ADR (a mensagem de erro precisa ensinar o agente a corrigir).
- Script `arch:check`; incluir em `verify`.
- **Fixtures de prova:** `test/architecture/fixtures/` com arquivos que violam cada regra, e um teste (Vitest) que roda o depcruise sobre os fixtures e espera uma violação por regra. Isso garante que as regras realmente funcionam.
- Os fixtures ficam excluídos da checagem normal de `src/`.

## Fora de escopo
- Testes de convenção de nome com ts-morph (avaliar na T6.08, quando houver código real).

## Critérios de aceite
- [ ] `pnpm arch:check` passa no código atual.
- [ ] O teste de fixtures prova cada regra: domain-pure, application-no-infra, no-cross-module, core-framework-free, integrations-isolated, no-circular.
- [ ] A mensagem de violação cita a regra e o ADR.

## Verificação
```bash
pnpm arch:check
pnpm test:unit test/architecture
```

## Notas / riscos
- A regra `no-cross-module` precisa de regex com grupo de captura (`src/modules/([^/]+)/` → proibir `src/modules/(?!$1)`). Verifique na documentação do dependency-cruiser o suporte a `$1` em `pathNot`.
