## Objetivo
Lint e format rápidos e estritos com Biome + preset Ultracite, compatíveis com os decorators do NestJS.

## Contexto para ler (e só isso)
- [AGENTS.md](../../../AGENTS.md)
- [11-code-quality.md](../../architecture/11-code-quality.md)

## Escopo
- Instalar `@biomejs/biome` e `ultracite` (versões exatas); `biome.json` estendendo o preset Ultracite.
- Ajustes necessários para NestJS: `unsafeParameterDecoratorsEnabled`, permitir classes com só membros estáticos onde o Nest exige (ex.: módulos), `useImportType` compatível com DI (**imports usados como tipos de injeção não podem virar `import type`**, senão a metadata de DI quebra).
- Regras exigidas: `noExplicitAny` = error, `noConsole` = error em `src/`, imports não usados = error, organização de imports.
- Scripts: `lint` (`biome check`), `lint:fix` (`biome check --write`), `format`.
- `verify` passa a incluir `lint`.
- Configuração do editor recomendada (`.vscode/extensions.json` e `settings.json` com o Biome como formatter).

## Fora de escopo
- Git hooks (T1.04).

## Critérios de aceite
- [x] `pnpm lint` passa no código da T1.01.
- [x] Um `console.log` ou `any` de teste em `src/` faz `pnpm lint` falhar (validar e remover).
- [x] Um controller com injeção via construtor continua funcionando depois de `pnpm lint:fix` (DI não quebrada por `import type`).
- [x] `pnpm verify` = `lint` + `typecheck`.

## Verificação
```bash
pnpm lint
pnpm lint:fix && pnpm build && pnpm dev   # health continua 200
```

## Notas / riscos
- O ponto mais comum de quebra é o `useImportType` com DI do Nest. Documente a regra adotada no `AGENTS.md` aninhado (T1.08).
