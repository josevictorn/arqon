## Escopo
- Root `AGENTS.md` (e `GEMINI.md` sincronizado):
  - Substituir a tabela de comandos pelos scripts reais; remover o aviso "disponíveis após a Fase 1".
  - Atualizar a hierarquia de verdade e regras inegociáveis para citar `docs/modules/<ctx>/spec.md` + `prd.md`, UUIDv7 no domínio (ADR-0014), JWT EdDSA/Ed25519 (ADR-0015), Tenant ativo por request `:orgId` / `X-Organization-Id` (ADR-0016), PostgreSQL RLS via `SET LOCAL app.current_tenant_id` (ADR-0017), Envelope de IntegrationEvent via ALS (ADR-0019) e JSON Schema via Zod (ADR-0020).
  - Registrar as armadilhas encontradas na F1 (ex.: `import type` vs DI).
- `AGENTS.md` aninhados, **curtos (≤ 30 linhas cada)**, só com regras locais e um exemplo de referência:
  - `src/shared/core/AGENTS.md`: zero framework; `UniqueEntityID` (UUIDv7 — ADR-0014); `IntegrationEventEnvelope` (ADR-0019); tudo 100% testado unitariamente.
  - `src/modules/AGENTS.md`: anatomia do módulo, consulta obrigatória a `docs/modules/<ctx>/prd.md` e `spec.md`, nomes de arquivo (`*.command.ts`, `*.query.ts`, `*.projector.ts`, `*.subscriber.ts`), isolamento RLS (`organizationId` + ADR-0017) e proibição de import cruzado.
  - `src/integrations/AGENTS.md`: Gateway + ACL + Factory explícita (sem fallback automático — ADR-0005) + resiliência `@Resilient` obrigatória; `jose` com `EdDSA` para JWT (ADR-0015).
  - `test/AGENTS.md`: níveis de teste (`unit`, `int`, `e2e`), onde ficam fakes e factories, exigência de testes anti-vazamento cross-tenant e idempotência.
- Revisar se algo no `docs/workflow.md` mudou com a prática da F1.
