## Objetivo
O read side tem uma conexão MongoDB gerenciada pelo ciclo de vida do Nest, um `MongoReadService.collection<T>(name)` tipado e um registro declarativo de índices por view: cada módulo declara as collections e os índices dela (inclusive TTL), e o boot cria os que faltam e **falha rápido** quando um índice existente diverge da declaração. Os testes de integração rodam cada worker num database Mongo isolado.

## Escopo
- **Dependência:** driver oficial `mongodb` (versão exata compatível com MongoDB 8). Sem Mongoose.
- **`src/shared/infra/database/mongodb/`**:
  - `MongoReadService`: `MongoClient` a partir de `MONGODB_URI` (connect no `onModuleInit`, close no `onApplicationShutdown`), `db()` e `collection<T extends Document>(name)`;
  - `MongoReadModule` (`@Global()`) com `forFeature(views: ViewDefinition[])` para os módulos registrarem as suas views;
  - `ViewDefinition = { collection: string; indexes: IndexDescription[] }` (nome explícito obrigatório em cada índice);
  - `ViewIndexSynchronizer`: no boot, para cada view registrada, cria os índices ausentes (`createIndexes`) e lança erro de boot se já houver um índice com o mesmo nome e especificação diferente. Índices extras não declarados **não** são removidos automaticamente.
- **Env nova:** `MONGO_SYNC_INDEXES_ON_BOOT` (boolean, default `true`) no `EnvModule` e no `.env.example`.
- **Isolamento de integração (Mongo)** em `test/support/mongo.ts`, chamado pelo `test/setup-int.ts`: database `test_<worker>_<uuid>` por worker, removido (`dropDatabase`) ao final.
- Atualizar `src/shared/infra/AGENTS.md` (views só por `MongoReadService`, índices só por `ViewDefinition`) e [10-testing.md](../../architecture/10-testing.md).

## Critérios de aceite
- [ ] int: com uma `ViewDefinition` de teste com índice único composto e um índice TTL (`expireAfterSeconds`), o boot do módulo cria os dois, e `listIndexes` devolve as especificações declaradas.
- [ ] int: subir de novo com a mesma definição é idempotente (nenhum erro, nenhum índice duplicado).
- [ ] int: alterar a especificação de um índice existente (mesmo nome, outra chave) faz o boot falhar com erro que cita a collection e o nome do índice.
- [ ] int: com `MONGO_SYNC_INDEXES_ON_BOOT=false`, nenhum índice é criado.
- [ ] int: `collection<TestView>("x").updateOne(..., { $inc })` funciona com o tipo do read model sem cast.
- [ ] int: dois arquivos `*.int-spec.ts` em paralelo usam databases diferentes, e o database é removido ao final.
- [ ] O app fecha a conexão Mongo no shutdown (`app.close()` em teste não deixa handle aberto, ou seja, o Vitest termina sem `--force-exit`).
- [ ] `pnpm verify` passa; `pnpm test:int` verde.

## Notas / riscos
- O replica set de 1 nó exige `directConnection=true` na URI local (já no `.env.example`). Não remova: transações e change streams futuros dependem do replica set.
- Veja a armadilha do MongoDB 8 em kernels Linux `6.19`–`7.0.13` no README, se o container não subir.
- `IndexDescription` com `name` obrigatório evita que o driver gere nomes diferentes para a mesma chave em versões futuras.
