# T1.09 — Script de inicialização de novo projeto (`pnpm init:project`)

- **Fase:** F1 — Fundação e tooling
- **Status:** 📝 Detalhada
- **Depende de:** T1.06, T1.08
- **ADRs:** [0012](../../decisions/0012-inicializacao-de-novos-projetos.md)
- **Branch:** `task/T1.09-project-initializer`
- **Tamanho esperado:** M

## Objetivo
Permitir transformar uma cópia limpa do `arqon-boilerplate` em um novo projeto com um único comando (`pnpm init:project --name meu-saas` ou modo interativo), renomeando o projeto, gerando `.env` com segredos e chaves criptográficas exclusivas e resetando o roadmap para o novo produto.

## Contexto para ler (e só isso)
- [AGENTS.md](../../../AGENTS.md)
- [ADR-0012](../../decisions/0012-inicializacao-de-novos-projetos.md)
- [T1.06 — Docker Compose com profiles](./T1.06-docker-compose.md)
- `package.json`, `docker-compose.yml` e `.env.example` resultantes das tasks anteriores

## Escopo
- Script `scripts/init-project.ts` (executável via `pnpm init:project` em modo interativo ou não-interativo `--name <slug> [--description "..."]`):
  - Valida que `<slug>` segue kebab-case (`^[a-z][a-z0-9-]*$`).
  - **Renomeação:** atualiza `package.json` (`name`, `description`, `version: "0.1.0"`), `.env.example` (`APP_NAME`, `APP_SLUG`, bancos, prefixos de cache/tópicos, bucket S3), `docker-compose.yml` (fallback default do `name:`), `README.md` e `AGENTS.md`.
  - **Bootstrap de `.env` + chaves criptográficas:** cria `.env` a partir do `.env.example` já parametrizado e gera automaticamente valores criptográficos frescos via `node:crypto` (segredos aleatórios e par de chaves assimétricas JWT novas em formato PEM/base64 para desenvolvimento).
  - **Reset do Roadmap:** remove os arquivos `docs/roadmap/tasks/T*.md` de construção do boilerplate (preservando `docs/roadmap/tasks/_template.md`) e substitui `docs/roadmap/ROADMAP.md` pelo template limpo de novo produto (`scripts/templates/PROJECT_ROADMAP.md`), mantendo intactos `docs/decisions/`, `docs/architecture/` e `docs/modules/*/spec.md`.
- Template `scripts/templates/PROJECT_ROADMAP.md` pronto para o fluxo de tasks do novo projeto.
- Teste automatizado (`test/` ou unit test do script) que copia os arquivos relevantes para um diretório temporário (`os.tmpdir()`), executa o inicializador com `--name acme-cloud` e verifica que:
  - nenhuma referência residual indevida a `arqon-boilerplate` permanece nos alvos;
  - `.env` foi criado com chaves válidas;
  - `docs/roadmap/tasks/T*.md` foram removidos e `_template.md` + novo `ROADMAP.md` permanecem.

## Fora de escopo
- Publicação do pacote externo `create-arqon-app` no npm e empacotamento final do CLI com todos os módulos de domínio (fica na **T11.03**, quando o boilerplate estiver completo).
- Remoção seletiva de módulos de domínio (os módulos só existem a partir da F6–F10).

## Critérios de aceite
- [ ] `pnpm init:project --name acme-saas` (rodado contra uma cópia em `/tmp`) conclui em < 3s sem erros.
- [ ] O `.env` gerado contém `APP_SLUG=acme-saas`, segredos únicos e par de chaves JWT gerado via `node:crypto`.
- [ ] `docs/roadmap/ROADMAP.md` na cópia inicializada é substituído pelo roadmap limpo do novo projeto e `docs/roadmap/tasks/T*.md` não existem mais (exceto `_template.md`).
- [ ] Teste automatizado do inicializador roda e passa em `pnpm test:unit` e `pnpm verify`.

## Verificação
```bash
pnpm test:unit
pnpm verify
```

## Notas / riscos
- Nunca executar `pnpm init:project` diretamente na working tree do próprio repositório `arqon-boilerplate` sem flag explícita ou confirmação: adicione uma trava de segurança se o git remote apontar para o repositório upstream do `arqon-boilerplate` (a menos que `--force` seja passado).
