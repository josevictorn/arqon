# T1.09 — Script de inicialização de novo projeto (`pnpm init:project`)

- **Fase:** F1 — Fundação e tooling
- **Status:** 👀 Em review
- **Depende de:** T1.06, T1.08
- **ADRs:** [0012](../../decisions/0012-inicializacao-de-novos-projetos.md), [0015](../../decisions/0015-jwt-assimetrico-eddsa-ed25519.md)
- **Branch:** `task/T1.09-project-initializer`
- **Tamanho esperado:** M

## Objetivo
Permitir transformar uma cópia limpa do `arqon-boilerplate` em um novo projeto com um único comando (`pnpm init:project --name meu-saas` ou modo interativo), renomeando o projeto, gerando `.env` com segredos e chaves criptográficas exclusivas (`Ed25519` para JWT + `MFA_ENCRYPTION_KEY`) e resetando o roadmap para o novo produto.

## Escopo
- Script `scripts/init-project.ts` (executável via `pnpm init:project` em modo interativo ou não-interativo `--name <slug> [--description "..."]`):
  - Valida que `<slug>` segue kebab-case (`^[a-z][a-z0-9-]*$`).
  - **Renomeação:** atualiza `package.json` (`name`, `description`, `version: "0.1.0"`), `.env.example` (`APP_NAME`, `APP_SLUG`, bancos, prefixos de cache/tópicos, bucket S3), `docker-compose.yml` (fallback default do `name:`), `README.md`, `AGENTS.md` e `GEMINI.md`.
  - **Bootstrap de `.env` + chaves criptográficas (ADR-0015):** cria `.env` a partir do `.env.example` já parametrizado e gera automaticamente valores criptográficos frescos via `node:crypto`:
    - Par de chaves assimétricas **`Ed25519`** (`crypto.generateKeyPairSync('ed25519')` em formato PEM/base64) para `JWT_PRIVATE_KEY` e `JWT_PUBLIC_KEY` + `JWT_KEY_ID` único;
    - Chave simétrica de 32 bytes (`crypto.randomBytes(32).toString('hex')`) para `MFA_ENCRYPTION_KEY` (AES-256-GCM dos segredos TOTP do módulo `iam`).
  - **Reset do Roadmap:** remove os arquivos `docs/roadmap/tasks/T*.md` de construção do boilerplate (preservando `docs/roadmap/tasks/_template.md`) e substitui `docs/roadmap/ROADMAP.md` pelo template limpo de novo produto (`scripts/templates/PROJECT_ROADMAP.md`), mantendo intactos `docs/decisions/`, `docs/architecture/`, `docs/events/catalog.md`, `docs/glossary.md` e `docs/modules/*/{prd,spec}.md`.
- Template `scripts/templates/PROJECT_ROADMAP.md` pronto para o fluxo de tasks do novo projeto (orientando também como customizar os planos comerciais em `src/modules/billing/domain/catalog/plans.catalog.ts`).
- Teste automatizado (`test/` ou unit test do script) que copia os arquivos relevantes para um diretório temporário (`os.tmpdir()`), executa o inicializador com `--name acme-cloud` e verifica que:
  - nenhuma referência residual indevida a `arqon-boilerplate` permanece nos alvos;
  - `.env` foi criado com chaves `Ed25519` válidas e `MFA_ENCRYPTION_KEY` de 64 caracteres hex;
  - `docs/roadmap/tasks/T*.md` foram removidos e `_template.md` + novo `ROADMAP.md` + `docs/modules/*/{prd,spec}.md` permanecem intactos.

## Fora de escopo

- Remoção seletiva de módulos de domínio (os módulos só existem a partir da F6–F10).

## Critérios de aceite
- [x] `pnpm init:project --name acme-saas` (rodado contra uma cópia em `/tmp`) conclui em < 3s sem erros.
- [x] O `.env` gerado contém `APP_SLUG=acme-saas`, segredos únicos e par de chaves JWT gerado via `node:crypto`.
- [x] `docs/roadmap/ROADMAP.md` na cópia inicializada é substituído pelo roadmap limpo do novo projeto e `docs/roadmap/tasks/T*.md` não existem mais (exceto `_template.md`).
- [x] Teste automatizado do inicializador roda e passa em `pnpm test:unit` e `pnpm verify`.

## Verificação
```bash
pnpm test:unit
pnpm verify
```

## Notas / riscos
- Nunca executar `pnpm init:project` diretamente na working tree do próprio repositório `arqon-boilerplate` sem flag explícita ou confirmação: adicione uma trava de segurança se o git remote apontar para o repositório upstream do `arqon-boilerplate` (a menos que `--force` seja passado).
