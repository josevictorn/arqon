## Objetivo
Ambiente local reproduzível com todos os serviços do blueprint, organizados em profiles e com healthchecks, além de um `.env.example` completo refletindo todas as variáveis exigidas pelas specs dos módulos (`iam`, `tenancy`, `billing`, `notifications`, `audit`) e pelos ADRs 0003–0020.

## Escopo
- `docker-compose.yml` com profiles (conforme ADR-0011):
  - `core`: postgres 16, mongodb 7 (**replica set de 1 nó**, necessário para transações e change streams), redis 7 / valkey.
  - `messaging`: redpanda (compatível 100% com Kafka API na porta `9092` + **Schema Registry HTTP API na porta `8081`** para o JSON Schema do ADR-0020) + Redpanda Console opcional.
  - `mail-storage`: mailpit (SMTP `1025`, UI `8025`), minio (API `9000`, Console `9001` + job de criação do bucket de avatares/arquivos).
  - `observability`: `grafana/otel-lgtm` (OTel Collector + Loki + Tempo + Prometheus + Grafana UI na porta `3001` com dashboard provisionado em `docker/grafana/`).
- Healthcheck em todos os serviços; volumes nomeados; imagens com tags exatas (sem `latest`).
- Parametrização de projeto conforme [ADR-0012](../../decisions/0012-inicializacao-de-novos-projetos.md): definir `name: ${APP_SLUG:-arqon}` no topo do `docker-compose.yml` e evitar `container_name` fixo sem prefixo, permitindo que múltiplos projetos criados a partir do boilerplate rodem simultaneamente sem conflito.
- `docker/` com as configs auxiliares (provisionamento do Grafana, scripts de init do Mongo replica set e bucket MinIO).
- `.env.example` completo e organizado por seção com todas as variáveis previstas nos ADRs e nas specs dos 5 módulos:
  - **App:** `NODE_ENV`, `PORT`, `APP_NAME`, `APP_SLUG`, `CORS_ORIGINS`
  - **Databases & Cache (`core`):** `DATABASE_URL`, `MONGODB_URI`, `REDIS_URL`
  - **Messaging (`messaging` — ADR-0004 / ADR-0020):** `KAFKA_BROKERS`, `SCHEMA_REGISTRY_URL`
  - **Auth, JWT Ed25519 & MFA (`iam` — ADR-0015):** `JWT_KEY_ID`, `JWT_PRIVATE_KEY` (`Ed25519` base64/PEM), `JWT_PUBLIC_KEY` (`Ed25519` base64/PEM), `JWT_ACCESS_EXPIRES_IN=15m`, `JWT_REFRESH_EXPIRES_IN=7d`, `MFA_ENCRYPTION_KEY` (32 bytes hex para AES-256-GCM do segredo TOTP)
  - **Storage & Mail (`mail-storage`):** `S3_ENDPOINT`, `S3_REGION`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET`, `SMTP_HOST`, `SMTP_PORT`, `MAIL_FROM`
  - **Billing & Payment Gateways (`billing` — ADR-0005 / ADR-0018):** `PAYMENT_DEFAULT_PROVIDER=stripe`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `ASAAS_API_KEY`, `ASAAS_WEBHOOK_TOKEN`, `ASAAS_BASE_URL`
  - **Observability & Audit (`observability` / `audit` — ADR-0006 / ADR-0013):** `LOG_LEVEL=info`, `LOG_SUCCESS_SAMPLE_RATE=0.1`, `OTEL_EXPORTER_OTLP_ENDPOINT`, `PERSONAL_SECURITY_LOG_RETENTION_DAYS=90`
- Scripts: `infra:up` (core), `infra:up:full`, `infra:down`, `infra:reset` (remove volumes).
- Documentar no `README.md` as portas e UIs.

## Fora de escopo
- Dockerfile da aplicação (pode virar follow-up), conexão da app com os serviços (F3).

## Critérios de aceite
- [ ] `docker compose --profile core up -d --wait` sobe saudável em < 60s.
- [ ] `docker compose --profile full up -d --wait` sobe tudo saudável numa máquina com 8 GB.
- [ ] Funciona em arm64 (Mac M-series).
- [ ] O Mongo responde a `rs.status()` com `ok: 1`.
- [ ] Mailpit (8025) e console do MinIO acessíveis.

## Verificação
```bash
docker compose --profile core up -d --wait && docker compose ps
docker compose exec mongodb mongosh --quiet --eval "rs.status().ok"
docker compose --profile full up -d --wait
```
