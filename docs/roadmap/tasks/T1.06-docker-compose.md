## Escopo
- `docker-compose.yml` com profiles (conforme ADR-0011):
  - `core`: postgres, mongodb (**replica set de 1 nó**, necessário para transações e change streams futuros), redis/valkey.
  - `messaging`: kafka (KRaft, 1 broker), schema-registry, UI opcional.
  - `mail-storage`: mailpit (UI 8025), minio (+ job de criação do bucket).
  - `observability`: `grafana/otel-lgtm` (OTel Collector + Loki + Tempo + Prometheus + Grafana UI na porta `3001` com dashboard provisionado em `docker/grafana/`).
- Healthcheck em todos os serviços; volumes nomeados; imagens com tags exatas (sem `latest`).
- Parametrização de projeto conforme [ADR-0012](../../decisions/0012-inicializacao-de-novos-projetos.md): definir `name: ${APP_SLUG:-arqon}` no topo do `docker-compose.yml` e evitar `container_name` fixo sem prefixo, permitindo que múltiplos projetos criados a partir do boilerplate rodem simultaneamente sem conflito.
- `docker/` com as configs auxiliares (otel-collector.yaml, prometheus.yml, scripts de init).
- `.env.example` com `APP_NAME`, `APP_SLUG` e todas as portas e credenciais de dev interpoladas.
- Scripts: `infra:up` (core), `infra:up:full`, `infra:down`, `infra:reset` (remove volumes).
- Documentar no `README.md` as portas e UIs.

## Fora de escopo
- Dockerfile da aplicação (pode virar follow-up), conexão da app com os serviços (F3).

## Critérios de aceite
- [ ] `docker compose --profile core up -d --wait` sobe saudável em < 60s.
- [ ] `docker compose --profile full up -d --wait` sobe tudo saudável numa máquina com 8 GB.
- [ ] Funciona em arm64 (Mac M-series).
- [ ] O Mongo responde a `rs.status()` com `ok: 1`.
- [ ] Mailpit (8025) e console do MinIO acessíveis.

## Verificação
```bash
docker compose --profile core up -d --wait && docker compose ps
docker compose exec mongodb mongosh --quiet --eval "rs.status().ok"
docker compose --profile full up -d --wait
```
