## Objetivo
Ambiente local reproduzível com todos os serviços do blueprint, organizados em profiles e com healthchecks, além de um `.env.example` completo refletindo todas as variáveis exigidas pelas specs dos módulos (`iam`, `tenancy`, `billing`, `notifications`, `audit`) e pelos ADRs 0003–0021.

## Escopo
- `docker-compose.yml` com profiles (conforme ADR-0011, versões do ADR-0003 e imagens do ADR-0021):
  - `core`: postgres 17, mongodb 8 (**replica set de 1 nó**, necessário para transações e change streams), valkey 8.
  - `messaging`: redpanda (compatível com a Kafka API na porta `9092` + **Schema Registry HTTP API na porta `8081`** para o JSON Schema do ADR-0020) + Redpanda Console.
  - `mail-storage`: mailpit (SMTP `1025`, UI `8025`), RustFS (API `9000`, Console `9001`; o healthcheck cria o bucket de arquivos) — substitui o MinIO, que deixou de publicar imagens públicas (ADR-0021).
  - `observability`: `grafana/otel-lgtm` (OTel Collector + Loki + Tempo + Prometheus + Grafana UI na porta `3001` com dashboard provisionado em `docker/grafana/`).
- Healthcheck em todos os serviços; volumes nomeados; imagens com tags exatas (sem `latest`).
- Parametrização de projeto conforme [ADR-0012](../../decisions/0012-inicializacao-de-novos-projetos.md): definir `name: ${APP_SLUG:-arqon}` no topo do `docker-compose.yml` e evitar `container_name` fixo sem prefixo, permitindo que múltiplos projetos criados a partir do boilerplate rodem simultaneamente sem conflito (portas do host parametrizadas via `*_PORT`).
- `docker/` com as configs auxiliares (provisionamento do Grafana, scripts de init do Mongo replica set e bucket S3).
- `.env.example` completo e organizado por seção com todas as variáveis previstas nos ADRs e nas specs dos 5 módulos:
  - **App:** `NODE_ENV`, `PORT`, `APP_NAME`, `APP_SLUG`, `CORS_ORIGINS`
  - **Databases & Cache (`core`):** `DATABASE_URL`, `MONGODB_URI`, `REDIS_URL`
  - **Messaging (`messaging` — ADR-0004 / ADR-0020):** `KAFKA_BROKERS`, `SCHEMA_REGISTRY_URL`
  - **Auth, JWT Ed25519 & MFA (`iam` — ADR-0015):** `JWT_KEY_ID`, `JWT_PRIVATE_KEY` (`Ed25519` base64/PEM), `JWT_PUBLIC_KEY` (`Ed25519` base64/PEM), `JWT_ACCESS_EXPIRES_IN=15m`, `JWT_REFRESH_EXPIRES_IN=7d`, `MFA_ENCRYPTION_KEY` (32 bytes hex para AES-256-GCM do segredo TOTP)
  - **Storage & Mail (`mail-storage`):** `S3_ENDPOINT`, `S3_REGION`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET`, `SMTP_HOST`, `SMTP_PORT`, `MAIL_FROM`
  - **Billing & Payment Gateways (`billing` — ADR-0005 / ADR-0018):** `PAYMENT_DEFAULT_PROVIDER=stripe`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `ASAAS_API_KEY`, `ASAAS_WEBHOOK_TOKEN`, `ASAAS_BASE_URL`
  - **Observability & Audit (`observability` / `audit` — ADR-0006 / ADR-0013):** `LOG_LEVEL=info`, `LOG_READ_SAMPLE_RATE`, `LOG_SLOW_THRESHOLD_MS=500`, `OTEL_EXPORTER_OTLP_ENDPOINT`, `PERSONAL_SECURITY_LOG_RETENTION_DAYS=90`
- Scripts: `infra:up` (core), `infra:up:full`, `infra:down`, `infra:reset` (remove volumes).
- Documentar no `README.md` as portas e UIs.

## Fora de escopo
- Dockerfile da aplicação (pode virar follow-up), conexão da app com os serviços (F3).

## Critérios de aceite
- [x] `docker compose --profile core up -d --wait` sobe saudável em < 60s. *(15s)*
- [x] `docker compose --profile full up -d --wait` sobe tudo saudável numa máquina com 8 GB. *(~38s a partir do zero, ~1,6 GB de RAM somados)*
- [x] Funciona em arm64 (Mac M-series). *(todas as imagens são multi-arch e rodaram nativamente em arm64)*
- [x] O Mongo responde a `rs.status()` com `ok: 1`. *(transação multi-documento também validada)*
- [x] Mailpit (8025) e console do RustFS (9001) acessíveis.

## Verificação
```bash
docker compose --profile core up -d --wait && docker compose ps
docker compose exec mongodb mongosh --quiet --eval "rs.status().ok"
docker compose --profile full up -d --wait
pnpm test:unit   # test/infra/local-infra.spec.ts guarda .env.example e docker-compose.yml
```

## Notas de execução
- **Conflitos resolvidos pela hierarquia de verdade:** versões seguem o ADR-0003 (PG 17, Mongo 8, Valkey 8) em vez de PG 16/Mongo 7; a variável de sampling segue o ADR-0013 (`LOG_READ_SAMPLE_RATE` + `LOG_SLOW_THRESHOLD_MS`) em vez de `LOG_SUCCESS_SAMPLE_RATE`.
- **ADR-0021:** Redpanda na mensageria local e RustFS no lugar do MinIO (imagens `minio/*` e `quay.io/minio/*` não são mais públicas — `401` em pull anônimo, verificado em 2026-11-02).
- **MongoDB × kernel da VM:** o MongoDB 8 recusa iniciar em kernels Linux `6.19`–`7.0.13` ([SERVER-121912](https://jira.mongodb.org/browse/SERVER-121912); correção no kernel `>= 7.0.14`). A primeira validação falhou com Docker Desktop 4.87.0 (kernel `7.0.12-linuxkit`); após atualizar o Docker Desktop (kernel `7.0.14-linuxkit`) todos os critérios passaram. O README documenta o diagnóstico em "Troubleshooting".
