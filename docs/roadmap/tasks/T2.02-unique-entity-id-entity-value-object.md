## Objetivo
Toda entidade do domínio nasce com identidade UUIDv7 (RFC 9562) gerada em memória, antes de qualquer persistência. `Entity` compara por identidade e `ValueObject` compara por estrutura, os dois imutáveis e sem framework.

## Escopo
- **Dependência (ADR-0027):** adicionar `uuid` `14.0.3` (versão exata) em `dependencies`.
- `src/shared/core/domain/unique-entity-id.ts` (único arquivo do repositório que importa `uuid`):
  - `UniqueEntityID.create()`: gera um UUIDv7 novo com `v7()` (timestamp Unix em ms nos 48 bits iniciais, versão `7`, variante `10xx`), **monotônico** no mesmo processo (IDs gerados no mesmo milissegundo saem em ordem crescente).
  - `UniqueEntityID.restore(value)`: reidrata um ID vindo da persistência (confiável, sem validação cara).
  - `UniqueEntityID.parse(value): Either<InvalidUniqueEntityIdError, UniqueEntityID>`: valida formato UUID **e** versão 7 com `validate(value) && version(value) === 7` (para entradas não confiáveis).
  - `toString()`, `toValue()`, `equals(other)`.
- `InvalidUniqueEntityIdError` (422, `COMMON.INVALID_ID`, `errors.common.invalid_id`) em `src/shared/core/errors/common-errors.ts`.
- `src/shared/core/domain/entity.ts`: `Entity<Props>` abstrata com `id: UniqueEntityID` (gerado quando não informado), `props` `protected` e `equals()` por identidade (mesma classe + mesmo `id`).
- `src/shared/core/domain/value-object.ts`: `ValueObject<Props>` abstrata com `props` congeladas (`Object.freeze`) e `equals()` **estrutural** profundo (primitivos, `Date`, arrays, objetos planos e VOs / IDs aninhados via `equals`).
- Testes `*.spec.ts`: formato e versão do UUID gerado, ordenação de 10 000 IDs gerados em sequência, `parse` com UUIDv4 / string inválida / UUIDv7 válido, igualdade de entidades (mesmo id e classes diferentes, ids diferentes) e de VOs (props equivalentes em instâncias diferentes, `Date`, arrays, aninhados).

## Notas / riscos
- **Como gerar o UUIDv7 está decidido no [ADR-0027](../../decisions/0027-uuidv7-com-biblioteca-uuid.md):** lib `uuid` (`v7`, `validate`, `version`), importada **só** em `unique-entity-id.ts`. Não use `crypto.randomUUIDv7()` do Node: ele não é monotônico dentro do mesmo milissegundo.
- `uuid@14` é só ESM e o projeto é CommonJS: funciona porque o Node (≥ 22.12) faz `require()` de ESM. Já verificado com o `tsconfig` do projeto. Se o `tsc`, o Vitest ou o `nest build` reclamarem, pare e reporte no plano, sem trocar de versão por conta própria.
- `uuid` em `shared/core` não viola o `arch:check`: a regra `core-framework-free` proíbe só framework e infra.
- A monotonicidade vale **por processo**. Entre réplicas, a ordem é só por milissegundo, o que basta para a localidade do B-Tree (ADR-0014).
- Para testes determinísticos de timestamp, use a opção `msecs` de `v7()` por um parâmetro interno, sem expor isso como API de produção.
