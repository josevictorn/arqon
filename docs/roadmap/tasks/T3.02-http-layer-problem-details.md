## Objetivo
Toda resposta de erro da API, seja `Left<DomainError>`, exceção HTTP do Nest (rota inexistente, método não permitido) ou exceção não tratada, sai num **único formato Problem Details** com `Content-Type: application/problem+json`, sem stack trace e sem vazar detalhes internos em `5xx`. O Fastify sobe com Helmet, CORS configurado por env e sem o auto-log de request.

## Pergunta que bloqueia (vira o ADR-0029)
1. **Formato:** o [07-i18n-and-errors.md](../../architecture/07-i18n-and-errors.md) mostra `{ code, message, statusCode, traceId, timestamp }` e chama isso de "RFC 7807", mas esses membros não são os da RFC (`type`, `title`, `status`, `detail`, `instance`; a RFC 7807 foi substituída pela RFC 9457). **Recomendação:** RFC 9457 de verdade, com extensões: `{ type: "about:blank", title, status, detail, instance, code, traceId, correlationId, timestamp }`, e `errors: [{ path, code, message }]` em erros de validação (T3.04).
2. **`Either` → HTTP:** como o controller transforma um `Left` em resposta. **Recomendação:** o controller chama um helper `unwrapOrThrow(result)` que lança `DomainErrorHttpException` (classe de `presentation`/`infra`, que estende `Error` e embrulha o `DomainError`). O filtro captura essa exceção. A alternativa é um interceptor que desembrulha o `Either` devolvido pelo controller, mas isso esconde o tipo de retorno do OpenAPI.
3. **Status de erro de validação de entrada:** `400` (`COMMON.VALIDATION_FAILED`) ou `422`? **Recomendação:** `400`. O `422` fica para regra de negócio (ex.: `COMMON.INVALID_ID` vindo do domínio).

## Escopo
- **`main.ts` / bootstrap HTTP** (`src/shared/infra/http/bootstrap/`):
  - `FastifyAdapter` com `logger: false`, `trustProxy` vindo da env nova `TRUST_PROXY` (default `false`) e `bodyLimit` explícito.
  - `@fastify/helmet` e CORS a partir de `CORS_ORIGINS` (com `credentials: true` e `x-organization-id` / `x-correlation-id` / `accept-language` nos headers permitidos).
  - Função `configureHttpApp(app)` usada pelo `main.ts` **e** pelos testes e2e, para os testes subirem a mesma configuração da produção.
- **`GlobalDomainExceptionFilter`** (`src/shared/infra/http/errors/`), registrado como `APP_FILTER`:
  - `DomainErrorHttpException` → `status = domainError.httpStatus`, `code`, `detail` = mensagem traduzida;
  - `HttpException` do Nest (404 de rota, 405, 413...) → `COMMON.*` equivalente;
  - qualquer outra coisa → `500` `COMMON.INTERNAL_ERROR`, com `detail` genérico (nunca a mensagem da exceção).
- **Porta `ErrorMessageTranslator`** (abstract class) usada pelo filtro, com implementação padrão que devolve o `i18nKey`. A T3.03 troca pela implementação com `nestjs-i18n`.
- **Helper `unwrapOrThrow`** (ou o mecanismo que o ADR-0029 decidir) + `DomainErrorHttpException`.
- Novos erros comuns em `src/shared/core/errors/common-errors.ts`, só os que o filtro usa (`code` + `i18nKey`): `COMMON.ROUTE_NOT_FOUND` e `COMMON.VALIDATION_FAILED`. O `500` **não** é `DomainError` (ADR-0026: `DomainError` é sempre 4xx), então use um código de infra (`COMMON.INTERNAL_ERROR`) definido em `src/shared/infra/http/errors/`.
- `traceId` lido de `@opentelemetry/api` (`trace.getActiveSpan()?.spanContext().traceId ?? null`). Passa a ter valor quando o SDK entrar (T3.08b). `correlationId` fica `null` até a T3.05b.
- **`src/shared/infra/AGENTS.md`** (+ symlinks `CLAUDE.md`/`GEMINI.md`, até 30 linhas), com as regras da camada HTTP. Incluir `src/shared/infra` em `NESTED_DIRS` de `test/infra/agents-md.spec.ts`. As próximas tasks da F3 acrescentam seções a esse arquivo.
- Atualizar [07-i18n-and-errors.md](../../architecture/07-i18n-and-errors.md) com o formato final.

## Fora de escopo
- Tradução real das mensagens (→ T3.03). Aqui o `detail` é o `i18nKey`.
- `ZodValidationPipe` e erros de validação de DTO (→ T3.04). Aqui só existe o código `COMMON.VALIDATION_FAILED`.
- Canonical log da requisição e log `error` do `5xx` (→ T3.08a). O filtro só expõe os dados (`errorCode`, `status`, a exceção) para o interceptor de log usar.
- Rate limit / `429` (→ T3.09). Circuit breaker / `503` (→ T3.10).
- Prefixo global ou versionamento de rota (`/v1`): ainda não decidido. **Não** adicione. Se for necessário, abra um ADR.

## Notas / riscos
- O controller de teste usado nos e2e fica em `test/` (ex.: `test/support/http-fixtures.module.ts`) para não criar rota de mentira em `src/`.
- `DomainErrorHttpException` estende `Error` de propósito: é uma exceção da fronteira HTTP, não um `DomainError`. Isso não viola o ADR-0026, mas deixe isso explícito no JSDoc.
- O Helmet com CSP padrão bloqueia o Scalar em `/docs`. Isso é tratado na T3.04; não afrouxe a CSP global aqui.
