## Objetivo
Três níveis de teste separados e executáveis independentemente, com suporte a decorators/metadata do Nest via SWC.

## Contexto para ler (e só isso)
- [AGENTS.md](../../../AGENTS.md)
- [10-testing.md](../../architecture/10-testing.md)

## Escopo
- `vitest` + `unplugin-swc` (ou equivalente) para emitir decorator metadata.
- Configuração com **projects** (ou 3 arquivos de config): `unit` (`src/**/*.spec.ts`), `int` (`src/**/*.int-spec.ts`), `e2e` (`test/**/*.e2e-spec.ts` ou `src/**/*.e2e-spec.ts`; decidir e documentar).
- Path aliases funcionando nos testes.
- `test/setup-unit.ts`, `test/setup-int.ts` e `test/setup-e2e.ts` como placeholders (o isolamento real de banco vem na T3.11).
- Exemplos mínimos: 1 unit trivial e 1 e2e do `GET /health/live` com `app.inject()` do Fastify ou `supertest`.
- Scripts: `test`, `test:unit`, `test:int`, `test:e2e`, `test:cov`; `verify` passa a incluir `test:unit`.
- Coverage com `@vitest/coverage-v8`; thresholds definidos por pasta mais tarde (registrar como follow-up).

## Fora de escopo
- Bancos isolados por worker (T3.11), factories e fakes (T3.11).

## Critérios de aceite
- [ ] `pnpm test:unit` roda só `*.spec.ts`; `pnpm test:e2e` roda só e2e.
- [ ] O e2e do health passa usando o `AppModule` real com Fastify.
- [ ] Um teste que injeta um provider via construtor funciona (prova que a metadata do SWC está ok).
- [ ] `@faker-js/faker` instalado.

## Verificação
```bash
pnpm test:unit && pnpm test:e2e && pnpm verify
```

## Notas / riscos
- Sem SWC configurado, o Vitest (esbuild) não emite `design:paramtypes` e a DI falha silenciosamente.
